# 設計書: 摩天楼 (Matenro) (MC6809 + 差し替え可能なサブ CPU)

## 1. 目的と範囲

富士通 FM-11 の「マンハッタンシステム」のように、**異種 CPU を 1 つのメモリに密結合**したマシンのシミュレータです。

* メイン CPU は MC6809 で、OS は **OS-9 Level 2** です。6809 側のメモリ、MMU、I/O は **sim09 に準拠**しています
  (`/export/nas/archives/MC6809/new-sbc09` の `src/` を元にしています。元のディレクトリは参照しただけで、変更していません)。
* サブ CPU は **8 ビットデータバスの CPU を 1 ファイルで差し込める**ようにしてあります。いま入っているのは **Z80** と **8088** です。
* 2 つの CPU は**物理 RAM を共有**し、それぞれ**自分の最大クロック**で、同時に動きます。
* ストレージは SD カード相当 (ディスクイメージ。生のデバイス `/dev/sdX` も指せます) で、6809 側 (OS-9) だけが持ちます。
  サブ CPU はディスクを直接は触らず、共有メモリとメールボックス経由で 6809 (OS-9) に頼みます (マンハッタンの方式と同じ考え方)。
* **Z80 では CP/M-80、8088 では CP/M-86 のプログラムが、OS-9 のコマンド `cpm` から動きます** (12 章)。
* FPGA (Tang Nano 9K / 20K) への実装は検討だけです → [FPGA.md](FPGA.md)。

> **FM-11 の再現ではありません。** FM-11 のマンハッタンシステムの資料やコードは見ていません。「異種 CPU がメインメモリを
> 共有する」という考え方だけを借りて、レジスタ構成を新しく設計しました。

## 2. 全体構成

```
                       +--------------------------------------------+
   OS-9 Level 2        |  物理 RAM 2MB  (8KB x 256 ブロック)         |
   +---------+  MMU    |  [0 ............ memsize) [memsize ..2MB)    |
   | MC6809  |-------->|   OS-9 が使う RAM          サブ CPU 用プール |
   | 2 MHz   |  XC_SHR |                                  ^          |
   +----+----+ (任意)  +----------------------------------|----------+
        |  I/O ページ $FF80                                | SMMU (128 x 8KB)
        |   $FFC9-$FFCD  XLINK レジスタ                     |
        +-----------------+                          +-----+------+
                          | ドアベル / メールボックス |  サブ CPU   |
                          +------------------------->| Z80 / 8088  |
                                                     | 8 MHz       |
                                                     +-------------+
   SD カード (ディスクイメージ) --- 6809 の I/O ($FFC0-$FFC8, sim09 のまま) だけ
```

## 3. サブ CPU の差し込み口 (`subcpu.h`)

CPU は `sub_cpu_ops_t` を 1 つ公開するだけです。マシンのほかの部分には触りません。

```c
typedef struct sub_bus {                 /* CPU から見たバス (マシンが渡す) */
    void *ctx;
    uint8_t (*mem_read)(void *ctx, uint32_t addr);   /* addr は addr_bits ビット */
    void    (*mem_write)(void *ctx, uint32_t addr, uint8_t v);
    uint8_t (*io_read)(void *ctx, uint16_t port);    /* 下位 8 ビットだけ使う */
    void    (*io_write)(void *ctx, uint16_t port, uint8_t v);
    uint8_t (*int_ack)(void *ctx);                   /* 割り込み受け付けサイクルのバイト */
} sub_bus_t;

typedef struct sub_cpu_ops {
    const char *name; const char *desc;
    int      id;            /* XID レジスタの値 (Z80=1, 8088=2) */
    int      addr_bits;     /* 16 / 20 */
    uint32_t max_hz;        /* そのグレードの最大クロック */
    void *(*create)(const sub_bus_t *bus);  void (*destroy)(void *);
    void  (*reset)(void *);
    int   (*step)(void *);                  /* 1 命令 (または割り込み受け付け / HALT 中の 1 スロット)、使ったクロック数を返す */
    void  (*set_line)(void *, int line, int level);   /* SUB_INT (レベル) / SUB_NMI (エッジ) */
    int   (*is_halted)(void *);  int (*int_pending_ok)(void *);
    uint32_t (*pc)(void *);  uint64_t (*insn_count)(void *);  void (*dump)(void *, FILE *);
} sub_cpu_ops_t;
```

**新しい CPU を足すには**: `src/xxx.c` を書いて `const sub_cpu_ops_t sub_cpu_xxx` を公開し、`subcpu.h` に `extern` を 1 行、
`xlink.c` の `registry[]` に 1 項目、`Makefile` の `SRC` に 1 ファイルを足すだけです (8 ビットバスの CPU なら 6502、6800、
8085、V20/V30 などが候補)。

### 3.1 Z80 (`src/z80.c`)

* 公式の命令すべて、IXH/IXL、`DD CB d op` のレジスタへのコピー、`SLL`、`IN F,(C)`、`OUT (C),0`、X/Y フラグ、MEMPTR (`WZ`)、
  割り込みモード 0/1/2、NMI、`EI` の 1 命令遅れ、HALT。T ステートは Zilog のマニュアルどおり (命令ごとの固定値)。
* 実装していないもの: バス要求/ウェイト、`INIR/OTIR` 系と繰り返しブロック命令の X/Y フラグの細かい副作用。
* 最大クロック: **8 MHz** (Z80H)。CMOS の Z84C00 は 20 MHz まであるので、`-subclock 20000000` で変えられます。

### 3.2 8088 (`src/i8088.c`)

* 8086/8088 の命令すべて (プレフィックス、文字列命令と `REP` (反復ごとに割り込み可能)、`MUL/IMUL/DIV/IDIV`、BCD 補正、
  `INT/INTO/IRET`、トラップフラグ、`STI` と `MOV SS` の割り込み 1 命令遅れ、0 除算)。8086/8088 の未定義の動き
  (`60-6F` が `70-7F` の別名、`C0/C1/C8/C9`、`82`、シフトの `/6`、`SALC`、`POP CS`) も実機どおりにしてあります。
  80186 以降の命令 (`PUSH imm`、`PUSHA` など) は**ありません**。
* クロック数は、8086 マニュアルの実行ユニットのクロック数に EA 計算を足し、**16 ビットの転送 (データ、スタック、ベクタ) 1 回ごとに
  4 クロックを足した**値です (8088 の 8 ビットバスの規則)。**プリフェッチキューとバスインターフェースユニットは作っていない**ので、
  命令フェッチで律速されるコードでは実機より速く出ます。
* 最大クロック: **8 MHz** (8088-2)。

## 4. メモリの考え方

### 4.1 物理 RAM

物理 RAM は **2MB** (8KB のブロックが 256 個) です。レベル 2 の 6809 の MMU (sim09 のまま: 8KB × 8 ページ × 2 タスク、
ブロック番号 8 ビット) が見るのはこの RAM です。

| 名前 | 内容 |
|---|---|
| `-m サイズ` (`memsize`) | **6809 (OS-9) が使える RAM**。既定は sim09 と同じ 2MB (全部)。`-m 1M` にすると下半分だけです |
| `memsize` から 2MB まで | **サブ CPU 用のプール**。6809 の MMU からは見えません (読むと `$FF`、書いても消える)。6809 は XLINK の**ウィンドウ**で触ります。`XC_SHR` を立てると MMU からも見えて、直接共有できます |

サブ CPU は、全部の 2MB を見られます (OS-9 が使っている RAM も)。**OS-9 とサブ CPU が同じブロックを取り合わない**ようにするのは
ソフトウェアの役目です: `-m 1M` で OS-9 を下半分に閉じ込めて、上半分 (ブロック `$80`-`$FF`) をサブ CPU が使う、というのがいちばん簡単です。
OS-9 の中でブロックを確保して共有するドライバは、まだありません (11 章)。

### 4.2 SMMU (サブ CPU のメモリ管理)

サブ CPU のアドレス空間は **8KB ブロック 128 個 (1MB)** に区切られ、各ブロックが物理 RAM のブロック (8 ビット) に写されます。
Z80 は先頭の 8 個 (64KB)、8088 は 128 個全部 (1MB) を使います。6809 の MMU と同じ作りです。

* リセット後の割り当ては `ブロック i → 物理ブロック (xbase + i)`。`xbase` の既定は `$80` (物理 `$100000` から。8088 の 128 ブロックで
  ちょうど上半分 1MB)。`-xbase` で変えられ、6809 側から `XE_MI`/`XE_MD` で書き換えられます。
* 6809 の I/O ページ (物理 `$7FE00`-`$7FFFF`) は RAM ではないので、サブ CPU からは読むと `$FF`、書くと無視されます。
* 範囲外 (物理 2MB より上) も読むと `$FF`、書くと無視されます。
* Z80 は `PC=0000` から、8088 は `CS:IP=FFFF:0000` (= 線形 `FFFF0` = ブロック 127 の末尾) から始まります。6809 側で、
  そこに最初の命令 (8088 なら `JMP FAR`) を置いてからサブ CPU を動かします (`os9/xrun.asm` がやっています)。

## 5. sim09 からの変更点

| 場所 | 変更 |
|---|---|
| `machine.h` `machine.c` | 物理 RAM を常に 2MB に (`physsize`)、6809 が見える範囲を `mainlimit` に (`memsize` または `XC_SHR` のとき `physsize`)。IRQ/FIRQ を**タイマとドアベルの OR** で決める `machine_update_irq()`。XLINK レジスタの I/O 振り分け。`machine_run` にサブ CPU の追従 (`xlink_catch_up`) と、追従中の時間刻み (`quantum`) の制限。パワーレジスタ (`$FF8F`) に `$A6` (終了コード 1) を追加 |
| `main.c` | `-sub -subclock -xbase -xload -xrun -xt -xcon -xquantum -L1`。既定が Level 2。6809 のクロックの既定が 2 MHz (sim09 は 1.8432 MHz) |
| それ以外 (`m6809.c` `dis6809.c` `console.c` `net.c` `vdisk.c` `dbg.c`) | 無変更 |

OS-9 Level 2 の ROM とディスクイメージ (`new-sbc09/os9/`) は**そのまま**動きます (`tests/matenro_test.py` が起動を確かめます)。

## 6. XLINK: 6809 側のレジスタ

I/O ページ (`$FF80` から) の $49-$4D、つまり **`$FFC9`-`$FFCD`** の 5 バイトです。sim09 の Level 2 の I/O ページは
`$FFD0`-`$FFFF` が OS-9 のベクタページ (コードとデータ) で、`$FFC0`-`$FFC8` がディスクなので、空いているのはここだけです。
そのため、**直接のレジスタ 3 つと、索引 + データの対**にしました。

| アドレス | 名前 | 読み | 書き |
|---|---|---|---|
| `$FFC9` | `XCTL` | 制御 | 制御 |
| `$FFCA` | `XSTAT` | 状態 | **ACK**: サブ CPU からのドアベルを消す (値は何でもよい) |
| `$FFCB` | `XID` | サブ CPU の種類 (0 = なし、1 = Z80、2 = 8088) | **ドアベル**: サブ CPU を呼ぶ (bit 7 = 1 なら NMI) |
| `$FFCC` | `XIDX` | 拡張レジスタの索引 | 同左。**bit 7 = 1 で `XDAT` に触るたびに索引が +1** |
| `$FFCD` | `XDAT` | 拡張レジスタのデータ | 同左 |

> **`XDAT` に読み書き命令 (`CLR` `INC` `ASL` など) を使わないでください。** 6809 のこれらの命令は先に 1 回読むので、
> 自動加算が余分に進みます。`LDA` / `STA` を使います。

`XCTL`:

| bit | 名前 | 意味 |
|---|---|---|
| 0 | `XC_RUN` | 0 = サブ CPU をリセットしたままにする。0 → 1 でリセットが外れる (CPU は最初から) |
| 1 | `XC_HOLD` | 1 = サブ CPU を止める (バスホールド) |
| 2 | `XC_SHR` | 1 = 6809 の MMU から、`memsize` より上のプールも見える |
| 3 | `XC_FIRQ` | サブ CPU → 6809 の割り込みに FIRQ を使う (0 = IRQ) |
| 4 | `XC_IEN` | サブ CPU → 6809 の割り込みを許可 |
| 7 | `XC_RESET` | 書くとサブ CPU のリセットを 1 回かける (読むと 0) |

`XSTAT`: bit0 `XS_S2M` = サブ CPU がドアベルを鳴らして 6809 がまだ ACK していない、bit1 `XS_M2S` = 6809 がドアベルを鳴らしてサブ CPU が
まだ ACK していない、bit2 `XS_HALT` = サブ CPU が HALT/HLT 中、bit3 `XS_RUN` = 動いている。

拡張レジスタ (`XIDX` の下位 7 ビット):

| 索引 | 名前 | 内容 |
|---|---|---|
| `$00`-`$03` | `XE_M2S` | メールボックス: 6809 → サブ CPU (6809 は読み書き、サブ CPU は読むだけ) |
| `$04`-`$07` | `XE_S2M` | メールボックス: サブ CPU → 6809 (6809 は読むだけ) |
| `$08` | `XE_MI` | SMMU の索引 (0-127) |
| `$09` | `XE_MD` | SMMU のデータ: サブ CPU のブロック `XE_MI` が写る物理ブロック |
| `$0A`-`$0C` | `XE_WA` | ウィンドウのアドレス: **物理** アドレス (21 ビット、上位バイトから) |
| `$0D` | `XE_WD` | ウィンドウのデータ: 読み書きするたびにウィンドウのアドレスが +1 |
| `$0E`-`$0F` | `XE_KHZ` | サブ CPU のクロック (kHz、上位バイトから) |
| `$10`-`$13` | `XE_CLK` | サブ CPU の実行したクロック数 (`$10` を読んだ瞬間の値を保持、上位バイトから) |

6809 から共有メモリへの入り口は 2 つあります。**(a) ウィンドウ** (`XE_WA`/`XE_WD`): 物理アドレスで、どんな OS・どんな MMU の設定でも
使えます (OS-9 のユーザプロセスからも)。**(b) 直接の共有**: `XC_SHR` を立てて、6809 の MMU のエントリにサブ CPU のブロックの
物理ブロック番号を書けば、普通のメモリとして読み書きできます。

## 7. サブ CPU 側のポート

I/O ポートの**下位 8 ビット**を見て、`$00`-`$0F` だけが有効です (Z80 の `OUT (n),A` の A、8088 の `OUT DX` の上位は無視)。

| ポート | 読み | 書き |
|---|---|---|
| `$00` | サブ CPU の種類 (`XID` と同じ) | |
| `$01` | 状態: bit0 = 6809 がドアベルを鳴らした (未 ACK)、bit1 = 自分のドアベルが未 ACK、bit7 = 1 | |
| `$02` | | **ドアベル**: 6809 を呼ぶ (`XS_S2M` が立ち、`XC_IEN` なら IRQ/FIRQ) |
| `$03` | | **ACK**: 6809 のドアベルを消す (INT 線が下がる) |
| `$04`-`$07` | メールボックス 6809 → サブ CPU | |
| `$08`-`$0B` | メールボックス サブ CPU → 6809 | 同左 |
| `$0C` | 割り込み受け付けで返すバイト (Z80 の IM 2 のベクタ、IM 0 の命令、8088 のベクタ番号)。既定 `$FF` | 同左 |
| `$0E` | | デバッグコンソール: 1 バイトをホストへ出す (`-xcon file`、既定は stderr) |
| `$0F` | | `$A5` = シミュレータを終了 (コード 0)、`$A6` = 終了 (コード 1)。テスト用 |

6809 → サブ CPU のドアベルは **INT 線をレベルで立てます** (サブ CPU が ACK するまで)。NMI は `XID` への書き込みの bit 7 で 1 回だけ
パルスを出します。

## 8. スケジューリング (同時に動く 2 つの CPU)

* 6809 は sim09 のとおり `m6809_run()` で、サブ CPU は `step()` で、どちらも**命令単位**で動きます。
* 時刻は**ピコ秒**で数えます。6809 は `total_cycles × 周期`、サブ CPU は `t_ps += クロック数 × 周期` です。周期は `10^12 / Hz` (整数)。
* 6809 が (最大 `quantum` = 16 サイクル ≒ 8µs) 進むたびに、サブ CPU を**6809 の時刻まで追いつかせます** (`xlink_catch_up`)。
  したがって、2 つの CPU の見え方のずれは最大でも 1 命令 + `quantum` 程度で、**毎回同じ結果になります** (決定的)。
* サブ CPU が HLT で割り込み待ちのときは、時間を進めるだけで命令を回しません。6809 も SYNC/CWAI で待っているときは、sim09 の
  「アイドルスキップ」でどちらも時間を飛ばします。
* 実時間に合わせる (`-max` なし) ときは、sim09 と同じく 6809 のクロックに合わせます。
* メモリの競合 (同時アクセスのウェイト) は**まだ作っていません**: 実機では 1 ポートの RAM をどちらかが待つ場面があり、
  FPGA 版の速さに影響します ([FPGA.md](FPGA.md))。

## 9. ストレージ (SD カード)

sim09 のディスクのまま: `$FFC0` に `$81` (読み) / `$55` (書き) を書くと、256 バイトのセクタを DMA します。ディスクイメージは
ファイルでも、SD カードの生のデバイスでも構いません (`-0 /dev/sdX`、書き込みに注意)。FPGA 版の `sd_disk.v` (SPI モードの SD カード、
512 バイトのブロックに 2 セクタ) もこの仕様です。ハードディスクにもフロッピーにも使え、OS-9 の RBF の `d0`/`d1` ドライバがそのまま使えます。

サブ CPU がディスクを使うには、6809 (OS-9) が**サーバ**になります: サブ CPU が共有メモリに要求を書いてドアベルを鳴らし、OS-9 の
プロセスが読み書きして、ドアベルで知らせます。この要求・応答の約束事の一例が、CP/M の BDOS 呼び出し用の要求ブロックです (12 章)。ディスクのセクタを直接頼む汎用の約束事は決めていません (11 章)。

* サブ CPU → OS-9 の**汎用のサービス要求の約束** (ディスクのセクタ、コンソール以外の装置)。今あるのは CP/M の BDOS 用 (12 章) だけです。
* メモリ競合のモデル (どちらかが待つ)。
* サブ CPU の逆アセンブル付きトレース (`-xt` は PC とレジスタだけ)。
* FPGA の RTL。

## 12. CP/M-80 と CP/M-86 のプログラムを OS-9 から動かす (`cpm` コマンド)

OS-9 のシェルから `cpm ファイル [引数]` と打つと、サブ CPU が CP/M のプログラムを**そのまま**実行します。

| サブ CPU | ファイル | 例 |
|---|---|---|
| Z80 (`-sub z80`) | CP/M-80 の `.COM` | `cpm hello.com abc` |
| 8088 (`-sub 8088`) | CP/M-86 の `.CMD` (8080 モデル、スモールモデル) | `cpm hello86.cmd abc` |

**方式**: サブ CPU は BDOS の呼び出し (Z80 は `CALL 5`、8088 は `INT E0h`) を実行すると、共有メモリの**要求ブロック**に関数番号と引数を書いて
ドアベルを鳴らし、返事を待ちます。6809 側の OS-9 プロセス `cpm` がドアベルに気づき、**OS-9 のシステムコールで**コンソール入出力とファイル操作を
して、結果を要求ブロックに書きます。つまり、**OS-9 が CP/M の BDOS の役を引き受ける**マンハッタン方式で、CP/M の CCP/BDOS/BIOS の
バイナリは使いません (入手していません)。ファイルは OS-9 のファイルそのもので、`cpm` を起動したときのデータディレクトリにあります。

### 12.1 要求ブロック (共有メモリ)

| オフセット | 内容 |
|---|---|
| +0 | 関数番号 (C / CL) |
| +1, +2 | 引数 DE / DX (下位、上位) |
| +4, +5 | DS (8088 のみ。FCB や文字列の場所はこの DS と DX から決まる) |
| +8 | 結果 A / AL |
| +9, +10 | 結果 HL / BX (下位、上位) |
| +11 | 結果 AH (8088) |
| +12 | **完了フラグ**: サブ CPU が 0 にしてからドアベルを鳴らし、6809 が最後に 1 を書く。サブ CPU はこれが 0 でない間、メモリを見て待つ |

要求ブロックの場所は Z80 が `FC80h`、8088 が `0000:0600` です。サブ CPU の側のスタブは `os9/cpm/z80shim.asm` と `os9/cpm/i8088shim.asm`
(`os9/cpm/mkshims.py` が `fcb` データにして `cpm.asm` に埋め込みます)。6809 → サブ CPU の割り込み (`XID` へのドアベル) は**使いません**
(完了フラグで待つので、プログラムが `EI`/`STI` していても余計な割り込みが入りません)。

### 12.2 メモリの使い方

* **Z80**: `0000` にゼロページ (`JP START`、のち `JP WBOOT`、`IOBYTE`、`CALL 5` 用の `JP BDOS`、`005C`/`006C` の FCB、`0080` のコマンドテールと
  既定の DMA)、`0100` から TPA に `.COM` を読み込む。`FC00h` から**スタブ** (WBOOT = `FC00`、BDOS = `FC06`)。`LD HL,(6)` で見えるメモリの上限は `FC06h` なので、
  TPA は約 63KB です。プログラムの `RET` は `0000` に戻り、ウォームブートとして扱います。
* **8088** (CP/M-86): INT `E0h` のベクタ (`0000:0380`) が `0000:0500` のスタブを指す。起動コード `0000:0540`、プログラムが `RETF` で終わったときの
  終了スタブ `0000:0580`、要求ブロック `0000:0600`、起動情報 `0000:0620`。8080 モデルは `1000:0000` にベースページ、`1000:0100` からコード (CS = DS = ES = SS = `1000h`)。
  スモールモデルはコードグループを `1000:0000` に、データグループを `2000:0100` に読み込む (DS = ES = SS = `2000h`、ベースページは `2000:0000`)。
  `SP = FFFAh`、スタックには終了スタブへの戻り番地を積む。リセットベクタ (`FFFF:0000` = 線形 `FFFF0`) に `JMP FAR 0000:0540` を置く。

### 12.3 実装している BDOS 関数

| 番号 | 内容 | 備考 |
|---|---|---|
| 0 | システムリセット (プログラムの終了) | `cpm` コマンドが終わり、サブ CPU を止める |
| 1, 2, 6, 9, 10, 11 | コンソール入力、出力、直接入出力、文字列出力 (`$` で終わる)、行入力 (`I$ReadLn`)、状態 | OS-9 の標準入出力 |
| 12 | バージョン | Z80: `0022h` (CP/M 2.2)、8088: `1022h` |
| 13, 14, 25, 24, 29, 32 | ディスクのリセット、選択、現在のドライブ、ログインベクタ、読み出し専用ベクタ、ユーザ番号 | ドライブは 1 つ (A:) だけ。ユーザ番号は無視 |
| 15, 16, 22, 19 | open、close、make、delete | 名前は FCB の `NAME.EXT` を OS-9 のファイル名に写す。FCB の割り当て表 (d0) に OS-9 のパス番号を入れる |
| 20, 21, 33, 34, 36 | 順次読み出し/書き込み、乱数読み出し/書き込み、乱数レコード番号の設定 | 128 バイトのレコード = OS-9 のファイルの 128 バイト。ファイル末尾が 128 の倍数でないときは `^Z` で埋める |
| 35 | ファイルサイズ | レコード数を r0-r2 に |
| 17, 18 | 検索 (first / next) | OS-9 のカレントデータディレクトリを読み、`NAME.EXT` が 8.3 に収まるものを `?` のワイルドカードで比較する。ディレクトリエントリのレコード数は最大 128 |
| 26 | DMA アドレスの設定 | 8088 では DMA のオフセット |
| 51, 52 (CP/M-86) | DMA ベース (セグメント) の設定/取得 | |
| その他 | 何もしない (0 を返す) | リネーム (23) は 255 を返す |

### 12.4 制約

* **BDOS レベルの互換**です。CP/M の CCP、BDOS、BIOS の実物は動かしておらず、BIOS を直接呼ぶプログラム (CP/M-80 で `JP` 経由の BIOS 呼び出し、
  CP/M-86 の関数 50)、ディスクのセクタを直接読むプログラム (`STAT` の一部、`SYSGEN` など)、割り当て表を使うプログラムは動きません。
* ワイルドカードの `open` / `delete`、リネーム、ファイルの属性 (読み出し専用など)、複数のドライブ、ユーザ領域は未対応です。ディレクトリの検索の
  レコード数は 128 までです。
* CP/M のファイル名は大文字ですが、OS-9 は大文字小文字を区別しないので、同じファイルに当たります (作ったファイルの名前は大文字になります)。
* サブ CPU は BDOS の返事を**ビジーウェイト**で待ちます。6809 側も短いビジーウェイトのあと `F$Sleep` で待ちます。
* 同時に動かせるのは 1 つのサブ CPU だけなので、Z80 の `.COM` と 8088 の `.CMD` は、それぞれ `-sub z80`、`-sub 8088` で起動したときに動きます。
* `cpm` が使うメモリ (サブ CPU のプール) と OS-9 のメモリは、`-m 1M` で分けます。
* 実物の CP/M ソフトでの検証は、(1) Z80 の命令セットを調べる ZEXDOC (67 項目)、(2) HI-TECH C の各パス (13 章) で行いました。
  どちらもこのリポジトリには入れていません (ライセンスと再配布の都合)。それ以外はこのプロジェクトで書いた小さなテストプログラム (下) です。
* Z80 のスタックを `LD HL,(6)` から始めるプログラム (HI-TECH C など) は、`FC06h` の下 6 バイトに最初の `PUSH` を書きます。スタブの WBOOT をそこ (`FC00h`)
  に置くと壊れるので、WBOOT は `FC30h` にあり、`FC00h`〜`FC05h` は空けてあります。

`nasm` (`cpu 8086` で 8086 に無い命令を禁止) と `tools/mkcmd.py` (`.CMD` ヘッダを付ける) で作ります。

## 13. シームレスな操作: OS-9 のプリプロセッサ → CP/M-80 の C コンパイラ

目標は「OS-9 側で作ったツールと CP/M 側のツールを、ひとつの作業として続けて使える」ことです。例として、C のソースを OS-9 で作ったプリプロセッサに通し、
CP/M-80 の C コンパイラ (HI-TECH C 3.09) でコンパイルして、できたプログラムを `cpm` で動かします。

```
OS-9 (6809)    cpp  prog.c  ->  prog.i                          os9/cpp/cpp.asm (6809 のアセンブラで書いた C プリプロセッサ)
CP/M-80 (Z80)  p1 prog.i prog.p1, cgen prog.p1 prog.as          cpm が Z80 で動かす
CP/M-80 (Z80)  zas -> prog.obj, linq (+ crtcpm.obj libc.lib) -> prog.com
OS-9 -> Z80    cpm prog.com
```

`cc80` (`os9/cc80/cc80.asm`) がこの順に `F$Fork` で起こします。`cc80 -r -v prog.c` で、コマンドを表示しながらコンパイルして実行します
(`-s` `-c` で `.as` `.obj` で止める、`-k` で途中のファイルを残す、`-t=dir` でコンパイラの場所を変える、`-D` `-I` は `cpp` へ渡す)。
HI-TECH C は、元のドライバ `C309.COM` が `$EXEC` で次のパスを起こす作りで、`cpm` の上では動かなかったので、各パスの引数 (元のドライバが作る
`$$EXEC.$$$` と OPTIONS から読み取ったもの) を `cc80` が直接並べます。

### 13.1 `cpp` (OS-9 のプリプロセッサ)

`#include` (`"..."` と `<...>`、4 段まで)、`#define` (引数あり/なし)、`#undef`、`#ifdef` `#ifndef` `#if` `#elif` `#else` `#endif`、`#error`、`#line` `#pragma` (捨てる)、
式 (`defined` `?:` `||` `&&` `|` `^` `&` `==` `!=` `<` `>` `<=` `>=` `<<` `>>` `+` `-` `*` `/` `%` `!` `~`、10 進/16 進/8 進/文字定数)、
コメントと行の継ぎ足し (`\`)、文字列の中を展開しない、引数を先に展開してから置き換える (C の規則)、再帰の防止 (展開中のマクロは展開しない)。
`#` と `##` は未実装です。出力の行末は CR (OS-9 のテキスト) で、`cpm` が CP/M へ渡すときに CR LF に変えます。`-ofile` で結果をファイルに書きます。

マクロは 64 本のハッシュ表 + 一列のヒープ (6000 バイト) に置き、置き換えの途中結果は展開の深さ (7 段) ごとのバッファ、引数は深さごとの引数ブロックに置きます。
`#if` の式は 16 ビット符号付きの再帰下降パーサです。作った途中で見つけた間違い (レジスタの上書き 5 件ほか) は `tests/cpp/*.c` で防いでいます。

### 13.2 `cpm` に足したもの

* `-p=dir`: プログラムと、現在のディレクトリに無いデータファイル (`crtcpm.obj` `libc.lib` など) を探すディレクトリ。
* `-k`: コマンドテールを大文字にしない (CP/M の CCP は大文字にしますが、HI-TECH C のパスは `-Ptext=...` のように大文字小文字を区別します)。
* `-b`: 拡張子による判定をやめて全部をバイナリ扱いにする。 `-d`: BDOS 呼び出しを標準エラー出力に出す。
* テキストファイル (`.C` `.H` `.I` `.AS` `.TXT` など) は OS-9 の CR と CP/M の CR LF + ^Z を相互に変換します。プログラムが閉じずに終わったファイルは、終了時に閉じて
  一時ファイル (`$CPMTn`) を消します。
* `STDIN` `STDOUT` `STDERR` という名前のファイルは OS-9 の標準入出力に結び付くので、`list a.txt ! cpm filter ! ...` のようにパイプやリダイレクトに使えます。
* 前のプログラムが残した呼び鈴 (XSTAT) を起動時に捨てます。残っていると、次の `cpm` が最初に「古い要求 (関数 0)」を受けて、すぐ終わってしまいました。

### 13.3 作る途中で見つけた間違い

| 症状 | 原因 | 直したところ |
|---|---|---|
| HI-TECH C のパスが終わってもプロンプトに戻らない。ZEXDOC が全部終わったあとで最初から始まる | `LD SP,(6)` で始まるスタックが `FC04h`〜 を書き、`FC00h` の WBOOT を壊した | WBOOT を `FC30h` へ (`z80shim.asm`) |
| 続けて 2 回 `cpm` を実行すると 2 回目がすぐ終わる | 1 回目が最後に鳴らした呼び鈴が残り、2 回目が古い要求を処理した | 起動時に XSTAT を確認 (`cpm.asm`) |
| 引数の無い `cpm` で `-Ptext=0` が `-PTEXT=0` になる | コマンドテールを大文字にしていた | `-k` を追加 |
| OS-9 の VRBF ファイルへのリダイレクトで、シェルの close で出力が閉じる | IOMan は close のたびにファイルマネージャを呼ぶ (PD.CNT が 0 でなければ閉じてはいけない) | `vdisk.c` で `PD.CNT` を確認、パスの記憶を PD のアドレスで引く |

### 13.4 確かめたこと

* `make test-mh` の `cpp` 5 項目: 引数なし/ありマクロ、入れ子、`#if` の式 (除算、シフト、ビット演算、16 ビット定数)、`-D`。

  `-DSMALL` で `small 36` になる (同じ OS-9 のセッションで 2 回続けて)。HI-TECH C は再配布できないため、`MATENRO_HTC` が無いときはこのテストを飛ばします。
