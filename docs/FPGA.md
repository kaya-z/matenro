# FPGA への実装の検討 (Tang Nano 9K / 20K)

> これは**検討書**です。RTL は XLINK と、Z80 をつないだ `z80_soc.v` (シミュレーションのみ、メモリは配列) までです。数字は 3 種類あり、本文では区別して書きます:
> **[実測]** 既存の sim09 の FPGA 版 (`new-sbc09/fpga/tn9k/build/fuzix_nohdmi`) の合成・配置配線のレポートから読んだ値、
> **[資料]** デバイスのデータシートなど公開資料の値 (手元の Gowin IDE には容量の表がなく、確認していません)、
> **[見積]** 一般的な傾向からの推定 (**測っていません**。オープンな Z80 / 8086 のコアのソースが手元にないため)。
> HDMI は検討の対象外です (指示どおり)。

## 1. 結論

| 構成 | LUT4 (見積) | 判定 |
|---|---|---|
| **Tang Nano 9K** (8,640 LUT4) + 6809 + **Z80**、HDMI なし | 約 7,200-7,400 (84-86%) | **入る見込み** (コアと XLINK は実測、調停だけ見積もり)。LUT は 1 割強の余裕。ただし 67.5MHz の配置配線 (Fmax が 72-76MHz、CLS は現行で 76%) が通るかは、つないで配置配線するまで分からない |
| Tang Nano 9K + 6809 + **8088** | 約 8,800-12,000 (100% 超が普通) | **入らない見込み** (6809 コアだけで 3,281 LUT4 [実測]) |
| Tang Nano 9K + HDMI (sim09 の FPGA 版は HDMI + 漢字で LUT 86% [`new-sbc09/docs/FPGA.md`]) + サブ CPU | 9,400 以上 | 入らない |
| **Tang Nano 20K** (20,736 LUT4 [資料]) + 6809 + Z80 または 8088 (HDMI あり/なし) | 約 9,400-14,100 (45-68%) | **余裕で入る**。両方のサブ CPU を同時に載せて切り替えることもできる |

**推奨**: まず 9K で「6809 + Z80 + XLINK」を試し (入れば最小構成)、8088 が必要な場合、または 9K の配置配線が通らない場合は 20K に移ります。

## 2. 手がかり: sim09 の 9K 版の実測 [実測]

`fpga/tn9k/build/fuzix_nohdmi` (HDMI なし、Level 2 の MMU を含む) の合成レポートの階層別の資源:

| モジュール | LUT4 (ALU を除く) | ALU | レジスタ | BSRAM |
|---|---|---|---|---|
| `cpu` (Greg Miller の MC6809 コア `mc6809i.v`) | **3,281** | 119 | 204 | 0 |
| `soc` (バス、MMU、ROM、レジスタの束) | 776 | 44 | 401 | 1 |
| `disk` (`sd_disk.v`: SPI の SD カードと DMA) | 469 | 62 | 311 | 1 |
| `timer` (`timer_rtc.v`) | 252 | 17 | 151 | 0 |
| `loader` (漢字データのローダ) | 176 | 0 | 126 | 0 |
| `acia` (UART) | 100 | 15 | 103 | 1 |
| `psram` (PSRAM コントローラ) | 77 | 14 | 104 | 0 |
| `arb` (PSRAM の調停) | 12 | 0 | 52 | 0 |
| `top` | 9 | 15 | 20 | 0 |
| **合計 (配置配線後)** | **5,458 / 8,640 (64%)** (LUT 5,142 + ALU 316) | | レジスタ 1,472 / 6,771 (22%) | **3 / 26** (12%) |

* CLS (論理スライス) の使用率は 76% (3,272 / 4,320)。配置配線は LUT の使用率が 8-9 割を超えると急に難しくなります。
* RAM 64KB は BSRAM (26 ブロック = 468Kbit で足りない) ではなく、パッケージ内の **PSRAM (64Mbit = 8MB)** に置いています。
* クロックは水晶 27MHz から PLL で **67.5MHz**、6809 の E は ÷36 で **1.875MHz**。PSRAM の読み出しが E の半周期に収まらないときは E を止めて
  待ちます (実効は約 1.54MHz)。PSRAM が安定して動く範囲は 54-74.25MHz (81MHz は誤り)、論理の Fmax は 72-76MHz です。
* ここに無かったもの: 漢字のローダを外すと −176、タイマを小さくすれば −100 程度は削れそうです。

## 3. サブ CPU のコアと XLINK の大きさ [実測 / 見積]

Z80 コアと XLINK は Gowin IDE で**合成して測った値** (配置配線はしていない)、8088 コアと調停は**測っていない見積もり**です。

| 部品 | LUT4 の目安 | 備考 |
|---|---|---|
| **Z80 コア [実測]** (TV80 `tv80s`、Mode 0 = Z80。hutch31/tv80、MIT) | **1,392 + ALU 54 = 1,446**、レジスタ 230、SSRAM 12 | 合成だけ。9K と 20K で同じ値。内訳: コア本体 1,122、マイクロコード `i_mcode` 224、ALU 8、レジスタファイル 6 (+SSRAM 12)、ラッパ 32。8MHz のタイミングは配置配線をしていないので未確認 |
| 8088 / 8086 コア (MCL86、Zet86 系) | 3,000-6,000 | マイクロコード ROM に BSRAM を 1-4 ブロック使うものが多い。バイト幅バスの 8088 版が望ましい |
| **XLINK + SMMU [実測]** (`fpga/rtl/xlink.v`: レジスタ、メールボックス、ドアベル、128 × 8 ビットの SMMU、ウィンドウのカウンタ、32 ビットのクロックカウンタ) | **377 + ALU 31 = 408**、レジスタ 201、BSRAM 1、SSRAM 16 | 9K (`GW1NR-9C`) と 20K (`GW2AR-18C`) で同じ値。合成だけ (配置配線はしていない)。読み出しポートが 2 つ (サブ CPU のアドレス変換と 6809 の読み出し) あるので表が BSRAM と SSRAM に二重に写っている |
| メモリ調停を 2 マスタに拡張 | 100-300 | 6809 側とサブ CPU 側、ウィンドウ DMA の 3 マスタになる |

合計の追加は **Z80 構成で約 1,950-2,150** (1,446 + 408 [実測] + 調停 100-300 [見積])、**8088 構成で 3,500-6,700** くらいです (コア 3,000-6,000 [見積] + 408 + 調停)。
1 章の表はここから出しました: 9K は 5,458 − 176 (漢字ローダを外す) + 追加分、20K の HDMI 付きは 7,430 (86% × 8,640) + 追加分です。

## 4. 9K で足りない理由と、20K を使う場合

| | Tang Nano 9K [資料] | Tang Nano 20K [資料] |
|---|---|---|
| FPGA | GW1NR-9 | GW2AR-18 |
| LUT4 | 8,640 | 20,736 |
| レジスタ | 6,480 (+ I/O 291) | 15,552 |
| BSRAM (18Kbit) | 26 (468Kbit) | 46 (828Kbit) |
| 外付けに見えるメモリ | PSRAM 64Mbit (8MB、パッケージ内、HyperRAM 系の 8 ビット DDR) | SDRAM 64Mbit (8MB、パッケージ内、16 ビット) |
| クロック | 27MHz 水晶 | 27MHz 水晶 |
| SD カード | microSD スロット | microSD スロット (ピン割り当ては作り直し) |
| HDMI | 付いている (今回は不要) | 付いている |

* 手元の Gowin IDE (`/usr/local/IDE`) は両方のデバイス (`GW1NR-9C`、`GW2AR-18C`) に対応しています (`share/device/` を確認)。
  20K のボードのピン割り当て (`.cst`) と、SDRAM のコントローラ (PSRAM のものは使えません) は**新しく用意する**必要があります。これが 20K の
  主な追加作業です。
* 20K では LUT に余裕があるので、6809 + Z80 + 8088 を**全部載せて、`XID` で選ぶ** (または `XC` のレジスタで切り替える) こともできます。
  シミュレータの `sub_cpu_ops_t` に対応して、RTL でも CPU を同じバス (メモリ・I/O・割り込み) に差し込む作りにします。

## 5. メモリ構成の検討 (共有メモリ)

### 5.1 1 ポートの外付け RAM を 2 つの CPU で使うと

PSRAM の読み出しは 67.5MHz で 12-20 クロック (178-296ns) [実測 / FPGA.md の記述]です。各 CPU のバスサイクルとの比:

| CPU | クロック (67.5MHz から作る) | 1 バスサイクル | PSRAM を占める割合 |
|---|---|---|---|
| 6809 | E = 1.875MHz (÷36) | 533ns | 33-56% |
| Z80 | 7.5MHz (÷9) | 3-4 クロック = 400-533ns | 33-74% |
| 8088 | 7.5MHz (÷9) | 4 クロック = 533ns | 33-56% |

6809 とサブ CPU を足すと**ほぼ 100% かそれ以上**になる場面があり、片方 (または両方) にウェイトを入れる調停が必要です。
Z80 は `/WAIT`、8088 は `READY`、6809 は E を止める (現行の方法) で待たせられます。どれだけ遅くなるかは、シミュレータに
**メモリ競合のモデルを入れてから**見積もるのが筋です (DESIGN.md の 11 章: 未実装)。

### 5.2 BSRAM のデュアルポートを共有領域にする (推奨)

Gowin の BSRAM は**真のデュアルポート**にできます。2 つの CPU が**同じ BSRAM を別々のポートから**読み書きすれば、調停も待ちもありません。

* 9K: 26 ブロックのうち現行で 3 つを使っていて、残り 23 ブロック = 約 46KB (8 ビット幅で 1 ブロック 2KB)。
  共有領域 16-32KB (メールボックスや受け渡しのバッファ、Z80 の速いワーク RAM) を BSRAM に置き、大きな領域 (OS-9 の RAM、Z80 の 64KB の残り)
  は PSRAM、という二層にします。
* 20K: 46 ブロック = 約 92KB。共有領域を大きく取れ、SDRAM の遅さを避けられます。
* 現行のシミュレータの SMMU (8KB ブロック単位の物理アドレス) はそのまま使えます: 物理アドレスの特定の範囲を「BSRAM」に割り当てるだけです。

### 5.3 Z80 の 64KB の置き方

Z80 の全空間 (64KB) を BSRAM に置くと 9K では 32 ブロック必要で入りません。PSRAM を使い、頻繁に使う 16-32KB (スタック、ワーク、
ISR) を BSRAM に写すか、キャッシュ (1 ライン 16 バイトなど) を置く、という選択になります。最初の版は「全部 PSRAM + 調停」で十分で、
BSRAM の共有領域は後から足せます。

## 6. クロック

* **9K, 現行の 67.5MHz (推奨)**: 6809 の E は 1.875MHz (最大 2MHz の 94%)、サブ CPU は ÷9 で **7.5MHz** (最大 8MHz の 94%)。
  実績のある PLL の設定がそのまま使えます。
* **9K, 72MHz** (27MHz × 8 ÷ 3、VCO 576MHz): E = 72/36 = **2.0MHz**、サブ CPU = 72/9 = **8.0MHz** と、**ちょうど最大クロック**になります。
  ただし PSRAM が検証された範囲 (54-74.25MHz) の端で、論理の Fmax (72-76MHz) とも重なるので、**タイミングが通るか分かりません**。
  64MHz は PFD が 1MHz になって PLL の下限 (3MHz) を割るので使えません。
* 20K: SDRAM 用に別の PLL を使い、CPU 側は同じく 1 つのシステムクロックの**クロックイネーブル**で作ります (同期設計。
  CPU 間の信号は同じクロックドメインなので、メールボックスの同期回路が要りません)。

## 7. ストレージ (SD カード)

* 6809 側のディスクは既存の `sd_disk.v` をそのまま使います (SPI モード、初期化 263kHz → 通常 11.25MHz、カードの 512 バイトのブロックを
  256 バイトのセクタの DMA で PSRAM とやり取り)。OS-9 の RBF ドライバは変わりません。シミュレータの「ディスクイメージ = SD カードの生デバイス」
  という扱いと同じです。
* サブ CPU は SD カードに**直接触りません**。XLINK のメールボックスで 6809 (OS-9) に頼みます。FPGA でも同じです。
* 20K では SD カードのピンが違うので `.cst` を作り直し、同じ SPI モードで使います (ピンは未確認)。

## 8. 進め方 (提案)

1. **XLINK の RTL** — **書きました** (`fpga/rtl/xlink.v`)。Verilator のテスト (`make -C fpga/sim`、43 項目: レジスタ、メールボックス、ドアベルと割り込み、SMMU、ウィンドウ、クロックカウンタ) は通り、Gowin で合成して 408 LUT を実測しました (`fpga/synth/run.sh 9k xlink fpga/rtl/xlink.v`)。
   **Z80 側は済み**: `fpga/rtl/z80_soc.v` (TV80 + XLINK + SMMU + RAM) で `os9/sub/sumz80.py` (C のシミュレータと**同じバイナリ**) を動かし、1+…+100 = 5050、1+…+10 = 55 が C と同じにメールボックスと共有 RAM に出ることを確認しました (`make -C fpga/sim soc TV80=…`、11 項目。テストベンチが 6809 の役で XLINK のレジスタを叩き、`xrun` と同じ手順: ウィンドウで読み込み → 起動 → ready → n を送る → 呼び鈴 → 返事)。
   **まだ**: `tests/mh/xlink_test.asm` と 8088 側、実際の 6809 コアとの接続。
2. **Z80 のコア** — TV80 を単体で合成して **LUT 数を実測しました** (`fpga/synth/run.sh 9k tv80s ...`、3 章)。
   **つないだ分**: Z80 (TV80 `tv80s`) のバス (メモリ、I/O ポート `$00-$0F`、割り込み応答 = M1+IORQ、NMI、HALT、バス要求) を XLINK につなぎ、メモリを SMMU 経由で物理 RAM に出す部分を `z80_soc.v` に書きました。合成したロジックは Z80 + XLINK + つなぎで **約 1,610 LUT + ALU 54** です (コア 1,043 + 238 + 8 + 7、XLINK 284、つなぎ 30; `fpga/synth/z80_soc_syn.v`、RAM を 1KB にして測定、配置配線なし)。
   **分周も済み**: Z80 は `clk / CLKDIV` のクロックイネーブル (67.5MHz ÷ 9 = 7.5MHz) で動きます。TV80 の `tv80s` は `cen` を 1 に固定しているので、`fpga/sim/mk_tv80s_cen.sh` が sed で `cen_i` ポートつきの `tv80s_cen` を作ります (TV80 のファイルはリポジトリに入れず、手元のものから作る)。CLKDIV = 2, 3, 4, 9, 12 で同じ 11 項目が通ります (1 は未対応)。遅いクロックのために、(1) NMI のパルスを次の `cen` まで保持、(2) コアが T2 のあいだずっと `di` を取り込むので、データバスの選択をサイクルの頭で決めて次のサイクルまで保持、(3) I/O の書き込みはサイクルの終わり (WR が上がるとき) に、最後のクロックのデータとポートで行う、を入れました。合成は CLKDIV = 9 で約 1,620 LUT (つなぎ 38、XLINK 288、コア 1,296 ほか)。
   **まだ**: sim09 の SoC (`new-sbc09/fpga/tn9k/rtl/sbc09_soc.v`) への接続、PSRAM の調停とウェイト、配置配線でのタイミング確認。
3. 9K で入らない / 通らなければ 20K へ。SDRAM コントローラとピンを用意し、8088 のコアを載せる。
4. 調停にウェイトを入れ、BSRAM の共有領域を足して、シミュレータの競合モデルと比べる。

**確認できていないこと**: 3 章の 8088 コアの LUT 数 (測っていません。コアのソースが手元にありません)、調停の LUT 数、Z80 を載せた 9K の配置配線とタイミング、20K のボードの SDRAM・SD・HDMI のピンと速度、72MHz でのタイミング、
候補のコアのライセンスと実際の動作。
